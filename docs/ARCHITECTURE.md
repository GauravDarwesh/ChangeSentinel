# Regulatory Monitoring Engine v2

## Pipeline

Source configuration -> resilient discovery -> URL registry -> concurrent fetch -> content extraction -> normalization -> SHA-256 change detection -> immutable evidence -> high-recall relevance -> structured AI analysis -> durable notification outbox -> ntfy -> Git state -> GitHub Pages console.

The monitoring layer is deterministic. It emits NEW_URL, CHANGED_URL, HTML_SOURCE_CHANGED, UNCHANGED_URL, REMOVED_URL, FETCH_ERROR, EXTRACTION_ERROR, and BASELINE_MIGRATION. A CHANGED_URL requires a changed source: when the raw bytes (or, for HTML, the comparison signature that ignores Cloudflare's rotating tokens) are unchanged, a text difference is recorded as BASELINE_MIGRATION with `migration_reason` `extractor_version` or `extraction_drift`. An empty "complete" discovery is treated as FAILED, a mass removal is held for confirmation, and with browser-only discovery a URL must be missing from two consecutive complete crawls before REMOVED_URL is reported (the first miss marks the record `missing_since`). AI is downstream intelligence and cannot change the deterministic change classification. Evidence writes are append-only; repeated operational observations have observation-specific event IDs so later failures do not overwrite evidence referenced by earlier reports.

## State

- data/latest.json: current URL inventory grouped by source; each record keeps a bounded `change_history` (newest first, with any AI verdict) and `last_changed_at`.
- data/snapshots/<url_id>-<content_hash>.txt: immutable normalized-text snapshots.
- data/snapshots/html/: immutable complete fetched HTML response snapshots. A new file is written only when the HTML comparison signature changes.
- data/snapshots/files/: original PDF, ZIP and workbook (.xlsx, .xls, .ods) bytes, named `<url_id>-<raw_hash>`, for the dashboard's viewers and cell-by-cell comparison.
- data/snapshots/botcheck/: bot-check or challenge pages a fetch received instead of the monitored page, saved for review (content-addressed, never overwritten). They are never compared as content and the baseline is kept.
- data/rule-tables/<url_id>-<raw_hash>.json: rows of the rule and field tables read from a PDF (regmon/pdf_tables.py): each cell, the row key, the codes its logic reads, its PDF page and any source defect; written once per version of the file. PDFium is not thread-safe and the scan reads resources on several fetch workers, so every PDFium call (this reader and OCR rendering) holds the one lock in regmon/pdfium_lock.py, which is Docling's own PDFium lock when Docling is installed.
- data/successions.json: next-period files of monitored documents (regmon/succession.py), found from the links in data/link-lineage.json: one entry per predecessor (`from`, `to`, monitor, listing page, periods, `follow`). A followed successor is fetched with its predecessor's monitor and its NEW_URL is compared with the predecessor's text (item codes, spec diff, registry impact, the AI's diff); the event, evidence and timeline carry `predecessor`. A second rule, `label_handover`, pairs a link that lost its label on a page ("Current" under "Instructions:") with the link new to the page that took it; a monitor that crawls such labels reads the new edition against the old one in the same scan (its NEW_URL events wait until the scan's pages are read) and the old one's REMOVED_URL carries `successor`. data/link-lineage.json records each link's `section` (the heading it sits under) for this.
- data/items/<SERIES>.json and data/items/index.json: the item catalog (regmon/catalog.py), rebuilt incrementally after each scan from the latest text of every monitored document. Each series file lists its facets once under `facets` (id → kind, the edition chain's first address as `line`, the member file's name without period or version, `current` edition, and `editions`: id → url, document, monitor, first read, report date, status), then one item per line: per facet, its versions `{at, attrs, src, status?, reread?}` or `{at, absent: true, src}` (`src` names the edition; status is omitted when final). A facet follows its document across editions (data/successions.json, `superseded_by`), so an unchanged next edition adds nothing. The index records each document's fingerprint (with `CATALOG_VERSION`) and raw hash, and per edition chain the codes it listed, so an unchanged document is not read again, a code it drops gets an `absent` version, and the same bytes read again correct facts in place. `history(code)` gives the current facts, effective dates and the timeline; the MCP `item_code_history` tool returns it as `catalog`, and the dashboard's Registry item sheet reads the series file from Pages.
- data/proposals.json: proposed revisions by form (regmon/proposals.py), rebuilt after each scan from data/link-lineage.json: proposal packages (a form page's proposal section, or one notice on a page listing many) merged by Federal Register document number, heading or OMB control number, each with its forms, stage (final, proposed, under review, request, extension), stated effective dates, publication date and documents (notices, drafts, item lists, letters). Items are matched to proposals by their forms (catalog.item_forms). data/calendar.json also carries item dates from the catalog (one entry per form and date, with `codes`) and proposals' effective dates, both with `basis` `catalog` or `proposal` and no `event_id`.
- config/registry.json: the item registry. Changed only by hand, by `python -m regmon.registry import`, or by owner-opened `[ChangeSentinel] Registry update` issues the dashboard prefills (registry-update.yml, `apply-issue`), validated as a whole before commit. config/registry-templates.json: one entry per report (scheme, regulator, form, schedules, code prefixes) the dashboard and seed requests fill from.
- data/evidence/<event_id>.json: event evidence and unified diffs; existing files are not overwritten.
- data/reports/<source_id>.json: latest per-source report. data/report.json combines the latest report of every active source (`source_runs` names each one's run).
- data/history/index.json: compact run history, the newest `history_runs` entries per source, written one entry per line.
- data/history/<run_id>.json: full historical run report.
- data/notifications.json: notification idempotency ledger for delivered events. Records older than a year are dropped on delivery, unless their event is still in `report.json` or the outbox.
- data/notification-outbox.json: durable pending notification events awaiting delivery.
- data/discovery/: source metadata, sharded inventories, checkpoints, and failure ledgers.

## Scale and safety

HTTP discovery resolves relative and absolute links with bounded concurrency; browser discovery remains an optional fallback. Fetching is concurrent and AI analysis uses bounded concurrency. Exact URL allowlists are part of the discovery checkpoint fingerprint, and recovered checkpoint inventories are filtered through the current source scope. Redirects are bounded and checked for internal/private destinations; DNS preflight reduces SSRF risk but is not a complete defense against DNS rebinding.

PDF, DOCX, XLSX, PPTX, CSV/TSV, JSON, XML (XSD, XBRL instances and linkbases, XSLT), RTF and text resources are normalized before comparison, and so are the older formats regulators still publish: Excel 97-2003 `.xls` (including the Excel 2003 XML and HTML-table files that carry an .xls name), Word 97-2003 `.doc`, PowerPoint 97-2003 `.ppt`, and OpenDocument `.ods`/`.odt`. Every workbook format becomes the same structured sheet/cell text (`regmon/workbook.py`), so an .xls, an .ods and an .xlsx compare the same way, and workbook originals are saved for the dashboard's cell-by-cell comparison. XML is compared element by element in the dashboard and, for XSDs, linkbases and XBRL instances, row by row by `regmon/spec_diff.py` (XBRL facts are keyed by concept, period, dimensions and unit, so renumbered contexts are not a change). Previous trusted baselines are preserved when discovery is incomplete.

## Legacy URL collision migration

`scripts/migrate_legacy_url_collisions.py` audits inventory IDs that map to the same current canonical URL. It is dry-run by default. An apply run requires an explicit source ID, refuses active sources, requires the same non-empty normalized hash and present snapshots for every colliding record, and refuses groups with conflicting pending AI work. It merges change timelines into the preferred record and edits only `data/latest.json`; immutable event evidence, snapshots, historical reports, run history, and sent-notification ledger entries remain untouched.

## Quality gates

- `scripts/golden_corpus_check.py` (CI) re-extracts every saved original produced by the current extractor version and fails if its text no longer reproduces the baseline. Hash-scoped quality sentinels also check minimum text coverage and critical form/instruction markers on three known difficult, table-heavy PDFs; repeating a truncated baseline does not by itself count as fidelity.
- `python -m regmon.validate_state` checks discovery metadata, inventory/report/ledger/outbox integrity and every snapshot/evidence pointer; the monitor runs it before committing state.
- `scripts/ai_eval.py` (AI Smoke Test workflow) scores the full decision pipeline on 15 historical parser-artifact diffs and 12 model-routed cases split evenly between relevant regulatory changes and cosmetic/irrelevant changes. Every model-routed case runs twice; release gates require at least 80% end-to-end accuracy, 80% semantic-AI-only accuracy, 80% per-case repeat verdict agreement, at least 12 distinct model-routed cases, and zero decision-source mismatches. Model-only accuracy and the case count are gated separately because the 15 suppressed cases are always scored correct and would otherwise mask a weak model. The workflow retries transient/invalid provider responses, reports the actual provider model ID per call to expose router variance, and keeps `openrouter/free` as the default. The workflow publishes a stable status on every PR, but invokes the provider only when AI-relevant files change.

## AI

CHANGED_URL analysis receives the actual before/after unified diff; work resumed from the backlog is diffed against the snapshot from before the change. NEW_URL analysis receives the current normalized content. The model must return exactly nine fields: relevant, topic, change_type, summary, impact, effective_date, affected_scope, actions, reason. AI is downstream to technical detection, and notification delivery failures do not discard generated alerts. When AI completes after a generic "Technical change detected" alert was delivered, an AI_ASSESSMENT follow-up is sent.

## Scout (new-page discovery)

`regmon/scout/` is a separate capability that never writes monitoring state. Pipeline: regulator profile (`config/scout.json`) -> polite client (robots.txt per RFC 9309, Crawl-delay, pacing, public-host and redirect checks, size caps, request/time budget, Retry-After) -> channel parsers (sitemap index/urlset with hreflang alternates, RSS/RDF/Atom with links inside descriptions, listing pages with item context and newest-first pagination) -> registry (`data/scout/registry/<regulator>.json`, one candidate per line, evidence filled only where missing) -> deterministic assessment (`regmon/scout/assess.py`, three outcomes with confidence bands and signals) -> review queue, coverage ledger, history.

- **Newness:** a channel's first successful read is its baseline. A URL is new only when a channel that already had a baseline lists it first; a channel added later gets its own quiet baseline. URLs found in `config/sources.json` or `data/latest.json` count as known.
- **Coverage:** statuses are judged against the declared plan per channel and regulator (COMPLETE, PARTIAL, DEGRADED, BLOCKED, FAILED). Paginated listings must reach already-seen items (the tail of a page) to count as caught up; a page whose dates rise down the list is not trusted as newest first, and about every four weeks (from the channel's baseline) a listing is read to `max_pages` without stopping early, so back-dated or re-filed items on page 2+ are still found. A depth-limited listing keeps everything it found when a later page fails (PARTIAL). In a channel's first inventory, items the publisher dated within the previous seven days are announced as new rather than filed as baseline. A robots.txt Crawl-delay above `max_crawl_delay_seconds` is honoured and reported under `slow_hosts`. A feed whose items are all unseen is flagged as a possible window rollover. Each profile states its known gaps.
- **Identity:** URLs are canonicalized exactly like the monitor (a test pins this); http is upgraded to https only for hosts a profile marks `prefer_https`. Translations linked through site-map hreflang alternates are kept as relationships to the original-language page, not separate findings.
- **Decisions:** `data/scout/decisions.json` records owner decisions per URL with an append-only log; `python -m regmon.scout review` applies them from an owner-opened issue and needs only the standard library.
- **Commits:** `scripts/commit_state.sh` takes the state path; the monitor's pathspec excludes `data/scout`, so neither job refuses because of the other's commits, while each still refuses when its own state moved.
- **Sources and metadata:** `python -m regmon.scout source` applies an owner-opened "Scout source" issue (one JSON request) to `config/scout.json`: create a regulator with its first channel, add a channel, or replace a regulator's metadata (names, region, languages, path hints, relevant/exclusion keywords, known gaps, active). The merged configuration is validated with the same parser the sweep uses. Relevant keywords count as positive evidence; exclusion keywords act like an out-of-objective type and never outweigh a recognised regulatory publication type.
