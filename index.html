Add Slack, Teams or a webhook

Alert channels are GitHub secrets, so the dashboard never holds their addresses. Add one under Settings → Secrets and variables → Actions in the repository; the next run delivers to it.

Slack
SLACK_WEBHOOK_URL — an incoming-webhook URL for the channel.
Microsoft Teams
TEAMS_WEBHOOK_URL — the URL of a Teams workflow “Post to a channel when a webhook request is received”.
Webhook
ALERT_WEBHOOK_URL — any https endpoint (n8n, Zapier, a ticketing bridge); add ALERT_WEBHOOK_SECRET to sign each alert.
ntfy
NTFY_TOPIC — the phone push channel used so far.

Each alert is tracked per channel: if one is down, the others still get it and only the missed channel is retried.

Documents (PDF, spreadsheets, ZIP) are always downloaded directly. A bot-check page is never compared as content: it is saved for review and the last good copy stays the baseline.

Scans start at 00, 06, 12 and 18 UTC. A monitor is checked on the first of those slots that falls inside its schedule, so a window must span at least six hours. Detection, evidence and alerts work the same at any cadence.

The dashboard cannot change monitoring directly. Continue opens a prefilled GitHub request; the owner-only workflow applies it.

Apply a preset

A preset sets the scan schedule, and the workspace or labels where it names them; other settings are kept. Continue opens a prefilled GitHub request; the owner-only workflow applies it.

Scheduled digests

One AI summary of a workspace's changes, sent to the alert channels.

Each change in a digest carries the AI's English summary and a short quote of the changed text in the regulator's own language. A digest is built by the first scan after its time, from the changes that scan history recorded in the period; with AI unavailable it is still sent, with a plain count instead of the overview.

Continue opens a prefilled GitHub request; the owner-only workflow saves config/digests.json.
