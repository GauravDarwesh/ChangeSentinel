How the XML File is Structured Each XML file contains financial data for one reporting entity and as-of date. The data in the file is organized into the following sections.
• Reporting File o Create date o Create time
• Report o Respondent Id o As Of Date o Series Id
• Item Data o Context used for data in a schedule o Value XML structure or schema: <?xml version="1.0" encoding="UTF-8"?> <reportin -in -05-20" createTime="09:30:47+05:00" xsi:noNamespaceSchemaLocation="RCInputXML-1.0-20160520.xsd"> <report series="FFIEC009a" asOfDate="2026-06-30" reporterId="12345"> <!-- Cover Page items --> <itemData confidential="N" estimated="N" mdrm=” FCEX1111”> <value>cover page value </value></itemData> <!-- Schedule items --> <itemData confidential="N" estimated="N" mdrm=” FCEX1111”> <value>reported value </value>context mdrm=FCEX9207 value=item code/></itemData> </report> </reportingFile> Important Notes:
1) In the Cloud Reporting Central application the series name should be fully listed in the XML as “FFIEC009a”, unlike the legacy Reporting Central application where the series name in the text file was “FIEC009A”.
2) The financial data items will have two MDRMs, which are highlighted above. The first MDRM will be for the Column MDRM and the second, context MDRM (always CEX59209) will be for either the Country, Total Region or Unallocated Codes which are found in Appendix A below.
Reporting File is a wrapper that encapsulates all the data in the file; it must include the create date and time of the file.
Report is a wrapper that encapsulates all the data items; it must include attributes to identify the respondent Reporter Id, the report As of Date, and the report Series Id.
Item Data is a wrapper that encapsulates the report data values for the reporting entity and as of date.
Important: The upload xml file created can have any name but must have a .xml file extension as the file type.

The RCInputXML -1.0- 20160520.xsd is not necessary for the creation of the xml file and will not be provided since it is part of the Reporting Central submission system.
We do not recommend opening the generated xml file with any third-party applications as those applications would not contain the framework and backend files on the Reporting Central system.
<reportingFile> ... </<reportingFile> A tag used to encapsulate all the data in the file. Note all tags must have an opening and ending version.
xsi:noNamespaceSchemaLocation="RCInputXML- 1.0-20160520.xsd" Attribute of the reportingFile tag which specifies the location of the Schema.
createTime=”09:30:47+05:00” Attribute of the reportingFile tag which specifies the time the file was created. For the createTime, use the value provided here.
createDate=”2016-08-13” Attribute of the reportingFile tag which specifies the date the file was created. For the createDate, use the value provided here.
xmlns:xsi="http://www.w3.org/2001/XMLSchemainstance" Attribute of the reportingFile tag which tells the schemavalidator that all elements used in the XML file are declared in the "http://www.w3.org/2001/XMLSchemainstance" namespace.
<report> ... </report> A tag used to identify the series name, the reporting entity and the as of date of the data. Note all tags must have an opening and ending version.
reporterId=”12345” Attribute of the report tag which specifies the respondent ID. Leading zeros of the respondent ID should not be included; therefore, this field does not have to be 10 digits unlike a text file format. Example: respondent ID 0000012345 is reported as 12345.
asOfDate=”2026-06-30” Attribute of the report tag which specifies the as of date of the report. YYYY-MM-DD format.
series=”FFIEC009a” Attribute of the report tag which specifies the series name.
<!-- Cover Page items --> <!-- Schedule items --> Optional reference item that the reporter can include in their file as reference points, for example to identify breaks between the Cover page and the Schedules. These do not need to be included in the XML file to submit. These can be named whatever the user wants to name them; those 4
XML Tag/Attribute Meaning/How Used provided are just examples but they do have to be in the <!-- --> format.
<itemData> ... </itemDate> A tag used to encapsulate the item and its value from the report. Note all tags must have an opening and ending version.
confidential="N" This series does allow for confidentiality requests;
however, the confidential tag for all rows should equal “N”.
Do not set this to “Y” as this provides no meaningful information to the report submission. Confidentiality requests should be sent to the local Reserve Bank contact.
estimated="N" This series does not allow for estimation for external filers.
The estimated tag for all rows should equal “N”. Do not set this to “Y” as this provides no meaningful information to the report submission. If you need to estimate your data please contact your Reserve Bank contact.
mdrm=”MDRM9999” Attribute of the itemData tag which identifies a specific item in the report. Attribute of the context tag which identifies a group of items in the report. Each item will have its own MDRM which are included in the Report Detailed Field Specifications below.
<value> ... </value> A tag encapsulated within itemData tag and contains the value of the item. Note all tags must have an opening and ending version.
value=”1” Attribute of the context tag which identifies the order of in the item group.
<context> ... </context> An options tag encapsulated within itemData tag used to identify the order of a variable list of items. Note all tags must have an opening and ending version.

Preparing the File Upload for the FFIEC 009a The FFIEC 009a is comprised of both financial and text fields. To minimize issues arising during the creation of the Reporting Central XML file, it is strongly recommended that institutions follow the process described below.
Field Values Financial data fields can have either positive, zero, or null values. Please only include reportable data in the submission file, do not zero fill in the report if the item has a null value.
Field Character Limits Standard financial data are reported in millions and allow entry of up to 14 digits, with no decimal places.
For nonstandard financial limits and text item character limits, see the below table.
Cover Page Item Name MDRM Field Length Field Type Reporting Institution CEXA9017 72 Text City CEXA9130 30 Text State CEXA9200 2 Text Legal Entity Identifier (LEI) of the Reporting Institution (Report only if already have an LEI) CEXA9224 20 Text Name CEXA8901 72 Text Title CEXAC496 72 Text Area Code/Phone Number CEXA8902 30 Text Statement by management of the reporting institution concerning the information reported above (optional).
CEXA5224 864 Text Field Labels The identifying label for both financial and text data is the eight-character MDRM descriptor listed in the tables below. Reporting Central uses the MDRM to identify individual report items in the file upload.
FFIEC 009a reports use two MDRMs, one for the Column Identifiers (MDRM1) and the other MDRM (MDRM2) for the Country Codes (see Appendix A for a full listing).
